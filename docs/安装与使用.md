# AI 问答日记 0.4.0：安装与使用

这是供自己和少量朋友试用的工程候选。新生成流程及10篇样本已做真实API对照，最终4.0.3写作提示候选被上游429限流阻止，未成功复测；具体效果与不足见同包《测试报告》。Obsidian宿主、Android、官方Sync及本人体验仍待验证。

## 安装

1. 使用 Obsidian 1.11.5 或以上，先备份仓库。首次试用建议新建一个空白测试仓库。
2. 解压 `ai-diary-0.4.0.zip`，把里面的 `ai-diary` 文件夹放到仓库的 `.obsidian/plugins/` 中。最终路径为 `.obsidian/plugins/ai-diary/manifest.json`，不要再多套一层文件夹。使用自定义配置目录时替换 `.obsidian`。
3. 重新载入 Obsidian，在设置 → 社区插件中开启“AI 问答日记”。
4. 打开插件设置，填写 API 根地址、模型名称，这两项会自动保存；填写本设备 API Key，点击保存凭据，再测试连接。立即测试或关闭设置页，也会先完成地址与模型的保存。其他设置仍使用页面底部的“保存设置”。

从旧版升级：先关闭插件，用新版 `main.js`、`manifest.json`、`styles.css` 覆盖旧安装目录中的对应三份文件，再开启插件。保留原来的 `data.json`、日记、问答与接续数据，不要删除整个插件目录。事件仍为 schema v1；不批量改写旧日记或原始消息。新周月回顾开关默认关闭，沿用已有资料授权选择。

设置页会显示保存状态。地址无效或写入失败时保留填写内容，连接测试不会悄悄使用旧配置。外部配置变化会拒绝覆盖；需要放弃本页填写时，点击明确标注的“载入最新设置”按钮。

服务地址示例为 `https://你的服务/v1`。有代理前缀就保留前缀；完整 `.../chat/completions` 地址也可识别。当前只实现 Chat Completions 兼容文本接口，不支持 Responses 或 Anthropic Messages，也不保证任意代理或任意模型兼容。没有统一模型后台，每位用户使用自己的服务账户。

密钥进入 Obsidian SecretStorage，普通 `data.json` 只存凭据名称。插件不显示保存的密钥；输入新值可替换，留空保持现有值。需要删除时可在 Obsidian 的凭据管理中处理。每台设备分别配置密钥。

## 每晚记录

点击功能区的书本图标，或用命令面板运行“AI 问答日记：打开日记对话”。插件在主工作区使用一个独立标签页；重复打开会聚焦已有标签。

点击“开始回顾”，AI 默认从今天早上的具体事情问起，再聊当时的感受和想法，逐渐回顾一天。也可以直接在输入区说你想记的事。“从某个方面聊”保留可定制入口，关闭全部入口也可以回顾。页面直接使用当前 Obsidian 主题的配色和字体。

默认 Enter 换行，Ctrl / ⌘ + Enter 发送；手机可用输入法语音转文字。AI 直接阅读自然对话，自行判断回应、深入或推进；时间顺序只是回忆线索，不是固定问卷。点击“继续问我”接着聊；“换个方向”里可以换问法、聊下一段时间或先不聊这件事。

“先不聊这件事”停止当前具体事项的主动追问，直到你自己重提；文字表达同样生效。收起的“已聊内容”中可以选择原文继续说。这只是原文导航，不用来决定提问或测量情绪。

随时点击页首“生成日记”，同一标签整页切到文章预览。点击“编辑正文”在同页修改正文和独立 AI 观察，完成编辑后回到阅读。返回对话会保留预览稿；输入框仍有未发送内容时，选择发送后生成或仅使用已发送素材。

生成时AI会先整理问答素材，再写成整篇日记；不增加用户确认步骤。通常比旧版多一次素材整理API请求，等待与用量随服务而定。事实整理失败时原回答与已有稿件保留。已整理部分以当前稿为准，新增部分继续聊，不从旧问题自动补回已删内容。

确认归档后正式保存。预览自动保存到接续数据中，尚不等于正式归档。两种正文风格可以在设置里切换，改风格不会自动重写历史日记。

## 历史资料与后续关心

历史读取默认关闭。需要时打开“允许参考历史资料”，每行填一个允许的 Markdown 文件或文件夹，例如 `日记` 或 `项目/创作.md`。只有这个范围内的相关片段可能发送到所配置服务；原始问答内部数据、恢复副本与历史 AI 观察不参与证据检索。关闭历史读取或移除路径后，后续请求立即按新范围处理。

允许日记历史后，AI 可以主动关心未结束事项。跳过具体事项的记忆跨日期保留，并随接续记录同步；不会因为改名入口或过了一天而自动解除。长期观察基于获准的实际记录，给出相关笔记链接；没有足够依据时可以不生成规律。没有按材料天数设定心理判断门槛。

新版会记录 AI 回应依赖的历史来源与版本。撤销授权或改写历史文件后，相关旧 AI 回应及其派生内容不会继续进入模型上下文，本地问答仍保留。旧版没有历史来源标记的 AI 消息继续可读，后续请求以用户原文重建线索，可能需要澄清部分上下文。体验索引不作为重新整合正文的额外事实来源。

AI 观察尝试提出综合性的认识、可能的关切和未说透的想法，并联系历史中的变化与反例。它们是可核对的解释，保留你的纠正空间。新版观察只读取获准原文，不把先前 AI 观察带入上下文；周月回顾也不作为下一轮的事实证据。

## 周记与月记

在设置中开启“自动生成周记和月记”，同时启用“允许参考历史资料”，在允许路径中包含日记目录，例如 `日记`，保存普通设置。

按自然周（周一至周日）和自然月回顾。日记归档后、插件启动时，或点页首“周/月回顾”，会补生成已结束周期。最后一天尚未确认记录时，启动检查不会提前生成本周期；确认归档后可以生成。生成状态和最近的回顾链接会显示在对话页，可以像普通笔记一样阅读和编辑。Obsidian 关闭时不在系统后台调用 API。

默认位置：

```text
周记/YYYY/开始日期_结束日期.md
月记/YYYY/YYYY-MM.md
```

回顾聚焦整体状态、发展、反复和可能的联系，按需要给可选择的建议。素材是获准的日记正文；周期外资料保留为历史对照，未记录的日子不补造。每篇注明记录覆盖与出处。

已有周记/月记不会自动覆盖，手动编辑会保留；检测到目标已被另一写入创建时，新稿保留为“备选”。跨设备离线同名文件仍需官方 Sync 冲突处理，当前本地并发检查不等同于真实双端验证。日记先完成归档，周期服务失败不撤销日记，可点“重试周月回顾”。停止或关闭插件会阻止后续模型调用，已开始的日记保存事务仍优先完成。

## 目录与补记

默认布局：

```text
日记/YYYY/MM/YYYY-MM-DD.md
原始问答/YYYY/MM/YYYY-MM-DD.md
原始问答/_数据/YYYY/MM/YYYY-MM-DD/<设备-实例>.md
原始问答/_版本/YYYY/MM/YYYY-MM-DD/<归档事务与版本>.md
```

日记与可读问答互链。`_数据` 用于恢复输入、草稿、事项与归档状态，`_版本` 用于恢复覆盖前的内容；请把这两个普通目录一起同步。可在 Obsidian 的搜索/文件显示偏好中降低这些辅助目录的干扰，不要通过删除文件来隐藏它们。

每天一篇，标签上的日期可以选择已有日期，也可以在日期笔记中运行“补记当前日期笔记”。首次打开会优先恢复尚未完成的会话；跨午夜接续保持原记录日期，点击“今天”开始今天。

每次补记前选择“追加到末尾”或“结合当前正文重新整合”。本次预览建立后保持该次模式，防止把追加片段误当成整篇正文。下一次补记重新选择。重新整合以当前正文和新增回答为准，不从旧问答恢复已删除段落。

正式归档后要修改全文，可在 Obsidian 正式笔记中编辑；已归档的预览为只读。保存时发现当前文件变化，会保留预览并要求按当前笔记重建或打开原文对照。管理标记被删除时，不猜测正文区域进行覆盖，使用追加或手动整理。

首次记录前可配置目录。已有接续数据后首版禁止自动更换目录，以免孤立记录；需要迁移时先备份，再进行显式迁移，不能只改目录名。

## Windows 与 Android 接续

在两端打开同一官方 Sync 远程仓库，并确认 Markdown、插件文件与相应配置的同步选项。各设备的 Sync 选项可能分别设置；不要假设插件文件和启用状态默认一致。官方说明：[Sync 设置](https://obsidian.md/help/sync/settings)。

在 Android 的仓库配置目录中同样安装插件；若通过 Sync 传递插件文件，等文件到达并确认三份安装文件齐全后再开启。Android 的配置目录可能被系统文件管理器隐藏，可启用隐藏文件显示或使用 Sync。然后填写该设备凭据并测试连接。

记录页的“本机记录已保存”只表示本设备写入完成。切换设备前等待 Obsidian Sync 完成传输；若日记先到、归档记录尚未到，插件会等待记录补齐。离线并发预览会保留版本供选择，正式日记冲突仍需在 Sync 与插件的提示中处理。官方冲突说明：[Sync 冲突处理](https://obsidian.md/help/sync/troubleshoot)。

这部分是安装步骤与最终验证脚本，当前尚未在真实 Windows↔Android 链路上验证。请依测试报告集中完成实机试用。

## 失败与恢复

- 鉴权失败：检查密钥、模型权限和服务地址。
- 限流/额度或网络错误：回答已先保存，使用“重试上次操作”；不必重复发送同一回答。
- 停止等待/超时：客户端不采用迟到结果，服务端处理或计费可能仍继续。
- AI 观察失败：正文仍保留，可继续编辑归档；观察会单独显示未完成。
- 输出格式不可读：对话为空时重试一次；观察可作一次格式/引用修复，不自动评判或改写情绪理解。仍失败时保留回答和正文，可以重试。
- 有未完成归档：点“恢复归档”，按事务标记补齐，避免重复追加。
- 接续块损坏、未知版本或前序未到：停止写入，保留原文件，先完成同步或从备份恢复；不要把异常文件清空。
- 用户手动修改过的问答汇总：后续更新前保留一份恢复副本在 `_版本`。

## 升级、回退与卸载

升级前备份整个仓库及旧插件安装目录。关闭插件，替换 `main.js`、`manifest.json`、`styles.css`，重开。首版使用 schema v1，不尝试猜测迁移未知版本；未来版本若有迁移，必须先按迁移说明备份。回退需要匹配对应数据 schema，不能只凭文件日期判断。

卸载插件后，正式日记和可读问答仍可作为普通 Markdown 阅读。卸载不自动删除日记、接续记录或恢复副本。给朋友分享安装包与说明即可，每人使用自己的仓库、Sync 账户和 API Key。

## 从源码构建

Node 22+，npm。执行 `npm ci`、`npm run check`、`npm run test:integration`、`npm run test:e2e`、`npm run package`。浏览器流程另运行 `npx playwright install chromium` 与 `npm run test:browser`。开发时运行 `npm run dev`。本轮没有新增或运行性能、单元测试。

`npm run eval` 默认运行 18 个合成中文多轮场景、两种风格各一次，不调用真实服务。显式真实评测使用环境变量 `AI_DIARY_BASE_URL`、`AI_DIARY_MODEL`、`AI_DIARY_API_KEY`，运行 `npm run eval -- --real --case=work --runs=1`；再按需扩展到全场景和多次重复。多轮对话、写作和观察会产生所选服务用量。报告区分实际请求、解码响应和待人工复核的六维体验，不记录密钥，也不读取私人仓库。细则见同仓库《问答质量评测》。

最终包位于 `dist/ai-diary-0.4.0.zip`，校验值在 `dist/SHA256SUMS.txt`。打包脚本仅包含明确列出的安装文件和说明，不携带测试仓库、node_modules 或凭据。本轮十篇虚构测试的源码、原始记录和截图放在单独的 `ai-diary-0.4.0-test-records.zip` 中。
