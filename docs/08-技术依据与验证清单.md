## 方案中的推断与默认值

1. 在小范围、单模型首版里，先用一个文本兼容适配器和非流式请求，比同时加入多协议和多模型更容易完成并验证。这是范围选择，不是某厂商性能承诺。
2. 对话采用分设备写入段、日记采用当前文件权威和版本检查，可减少 Sync 覆盖风险。这是待验证的应用设计，不是官方提供的事务或通用同步保证。
3. 凭据默认每台设备配置，不以密钥自动同步为产品前提。最终以实际版本验证与安装说明为准。
4. 至少两个不同日期才提出谨慎重复模式，是证据门槛默认值，不是统计学或临床结论。
5. 默认检索 Markdown、自然随笔为初始风格、AI 观察初始折叠、应用界面中文；这些可在完整版本试用后调整。

## 避免错误承诺

- 填好 URL 与 Key 不等于已经可调用；目录同步不等于实时协同。
- SecretStorage API 的存在不等于所有版本、平台、跨仓库隔离和密钥同步都已实测。
- `Vault.process` 解决本地读写竞态，不等于跨设备全局锁。
- 非流式超时或取消不等于上游连接、推理或计费一定停止。
- 假模型、浏览器视图和窄屏测试不能代替真实模型质量、Obsidian 宿主和 Android 检查。
- 通过合成评测不能保证任意模型永远不幻觉；程序的来源限制、回归与最终预览一起构成控制。

这些边界应进入开发报告与测试说明；普通记录界面只呈现用户采取行动需要知道的信息，不堆放技术免责声明。
