# 验收与发布手册

以下是验收标准；当前实际执行范围见 [测试报告](测试报告.md)。测试样例使用合成资料；不把用户私人日记提交到仓库或模型评测服务。

## 测试层次

| 层次 | 方法 | 能证明什么 |
| --- | --- | --- |
| 单元 | 事件 reducer、权限、路径、消息水位、请求版本、schema | 确定性规则 |
| 集成 | 内存 Vault / 临时测试仓库、假模型与网络 | 模块配合、恢复、事务和失败路径 |
| 视图端到端 | 可交互浏览器 harness 或 Obsidian 测试仓库 | 流程、输入法、页面状态和按钮；浏览器 harness 不等于真宿主验收 |
| AI 场景评测 | 固定合成输入、真实所选服务、多次运行 | 模型输出在测试场景下的事实、重复、措辞与引用质量 |
| 真机与 Sync | Windows ↔ Android 的实际文件到达和接续 | 真实运行和官方同步链路 |
| 用户试用 | 完整版本集中反馈 | 是否像盘问、正文像不像本人、回看价值 |

代码覆盖率不替代下面的关键用例。真实模型评测与真机环境缺失时明确列为未执行，不能用假模型结果冒充。

## AI 评测集

建立至少 12 个有明确预期的场景文件，记录输入消息、当前正文、允许证据、事项状态、禁止输出和评审要点。覆盖：工作烦躁、家庭关系、长段强情绪、普通无事、只有一条素材、否定 AI 推测、改稿删除、跳过事项、历史模式、证据不足、提示注入、长会话摘要。

正文两种风格均运行；真实模型场景每种至少跑三次，记录服务、模型 ID、时间、提示词版本、结果和失败实例。若服务不可用，先完成评测运行器和假响应测试，将真实评测留为未执行。

硬性失败：虚构当天事件；把猜测写进正文；恢复已删正文；主动追问被抑制事项；读取未允许资料；编造历史链接。任一失败不得用平均分掩盖，修复后重跑关联场景。

辅助主观评分使用 1—5 分：提问自然度、问题有效性、个人语气、细节保留。建议以各项至少 4 分作为首轮调优目标，这是工程评测默认值，不代表用户已承诺接受该分数。模型裁判只能辅助，不能单独证明“像用户本人”。

## Windows 与 Android 检查

最终版本试用前，Agent 完成可用环境下的下列检查；无法执行的条目集中交给用户最终试用。

1. Windows 测试仓库安装与开启插件；使用系统深浅主题、窄窗口、不同字体缩放。
2. Android 打开同一独立视图，检查软键盘遮挡、输入法语音转文字、多行、触控和切后台恢复。
3. 各设备单独配置凭据，验证普通配置可用而密钥未混入仓库文件。
4. Windows 记录并保存到本机，等待官方 Sync 传输，在 Android 接着聊；再反向验证。
5. 在电脑已有编辑预览时收到手机新记录，保留两边，不静默替换用户草稿。
6. 跳过旧事项后换设备，主动关心不得重新触发。
7. 测试临时离线、同日并发、修改正式笔记、未完成归档和重复点击。

桌面窄屏和移动模拟用于提前发现布局问题，不代替 Android WebView、软键盘、文件和 Sync 测试。安装说明必须列出已测试的 Obsidian / Android 版本，不能只写“支持所有手机”。

## 工程命令契约

M1 创建对应 package scripts，之后交付至少可执行：

```text
npm ci
npm run check
npm run test
npm run test:integration
npm run test:e2e
npm run eval
npm run build
npm run package
```

eval 明确区分模拟与真实服务模式，缺凭据时输出“未执行真实模型评测”，不是返回伪成功。环境与运行依赖在锁文件固定；报告记录真实命令和退出结果。当前规划仓库尚无这些脚本，不应在规划阶段宣称运行成功。

## 小范围交付包

建议首次版本为 0.1.0，plugin ID 由 M0 冻结后保持稳定，暂用 `ai-diary`。

包应包含可安装目录中的 `manifest.json`、`main.js`、`styles.css`，并附中文安装说明、CHANGELOG、已知问题、数据目录说明和回退步骤。源码包含锁文件、测试 fixtures 和提示词；不携带测试仓库私人数据、node_modules、密钥或未审查的调试输出。

安装手册说明将插件目录放入仓库配置目录的 plugins 子目录、重载并开启社区插件；使用自定义配置目录时按该目录安装。Android 与 Sync 的具体步骤以实际测试结果写清，不假设插件列表和插件文件自动同步设置都已开启。

提供构建产物校验值及生成命令；打包后在干净测试仓库载入，不能仅检查文件存在。共享给朋友的是插件包与说明，每人配置自己的模型和仓库；不共享用户的日记、同步凭据或 API Key。

## 回退与最终试用

发布前保留旧插件包及数据迁移前副本。回退优先恢复插件版本；涉及 schema 变化时按迁移记录恢复对应数据，不凭文件日期猜版本。不自动删除归档日记和问答。

完整版本交付后请用户集中体验一个普通晚上和一个想深入聊的晚上，检查：是否愿意开始、什么时候觉得被盘问、哪些用词不像自己、重要细节是否留下、AI 观察是否有依据、双端是否能接上。

用户反馈先按数据与事实问题、体验问题、可选增强分级。全部必要修订与相关回归完成后，才可标记该小范围版本已验收。公开社区提交、上传、发布和代发给朋友不包含在开发完成的默认动作中。
