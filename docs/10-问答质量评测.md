# 问答质量评测

> 本文保留 0.2.0 的固定语料评测历史。0.2.1 已移除角度规则；本轮使用自适应虚构用户与当前真实 API，方案见 `11-自然回顾与主题适配.md`，实际输出和评分见当前《测试报告》。不将下文旧规则或旧 not-run 状态作为当前结论。

日期：2026-10-12。面向 0.2.0。评测素材全部为合成中文文本，不使用用户日记或真实凭据。

## 评测分成三种证据

1. **工程契约**：引用是否来自用户原话；拒绝、同片段同角度的重复、伪造来源和删除保护是否被程序处理。通过测试表示程序在这些具体输入上的行为正确。
2. **真实服务回放**：把固定的合成多轮用户发言交给所选服务，保留逐轮输入、输出、动作、来源、最终成文和错误。通过格式校验不代表问题有价值。
3. **人工与真人体验**：人工阅读真实回放，按下表独立评价；本人语气、表达意愿、回看价值和界面体验需要最终集中试用。合成用户不会根据新问题改变回答，因此不能替代真人对话。

评测不让同一模型给自己的回答打分，不把出现更多情绪词、问更多问题或生成更长文章当作质量提升。不合并六个指标为一个自动“质量通过率”。

## 场景

`tests/fixtures/evals.ts` 包含 18 个多轮场景，每个至少三个交互：模糊的一天、工作落差、纠正推测、长段强情绪、事实列表、混合感受、正向小事、平淡、记不清、明确拒绝、重复念头、三段体验变化、历史分离、打断接续、编辑删文、材料注入、超过四十条对话、主动换向和结束。

每个场景提供关注点和合成契约回应。合成回应明确由脚本返回，用于走完整生产 `DiaryApp` 流程，**不能用其措辞、留白比例或优美程度证明真实模型更好**。真实模式忽略这些预编回应。

默认运行两个写作风格，各一次。`--runs=3` 可以在真实服务中重复，最多五次。长场景的两种风格各会发起二十余轮对话，运行真实模式前先选一个场景，控制请求与费用；网络/解析修复可能增加请求数。

## 运行

```powershell
npm run check
npx vitest run tests/evals
npm run eval
npm run eval -- --case=work --runs=3
```

以上评测命令默认只运行内存仓库和确定的合成回应，不联网。

真实模式必须显式加 `--real`，并由操作者在当前进程环境提供 `AI_DIARY_BASE_URL`、`AI_DIARY_MODEL`、`AI_DIARY_API_KEY`。脚本不会从插件设置、Codex 配置、用户仓库或系统凭据读取 Key；缺失变量以退出码 2 结束，不退回合成模式。不要把 Key 写进版本库、截图或报告。

```powershell
npm run eval -- --real --case=work --runs=1
# 完成小规模检查后，再按需运行完整固定回放：
npm run eval -- --real --runs=3
```

输出：

- `test-results/eval-contract.json`：合成多轮契约证据。
- `test-results/eval-real.json`：只有显式真实模式才写入；包含合成用户与真实模型的完整输入/输出，可人工复核。
- `test-results/eval-*-review.md`：六维人工复核空表，脚本不会代填分数。
- `test-results/eval.json`：最后一次运行的报告，保留旧路径兼容；必须看 `mode` 和 `realModelExecuted`，不能沿用旧版 72/72 的解释。

报告不记录请求头、Key 或服务地址。模型名和模型原始文本会写入本地评测报告。输出只证明当前提交/工作区、当前提示词版本、当前模型配置和实际记录的回放。

## 六个独立维度

| 维度 | 人工要检查什么 | 1 分锚点 | 5 分锚点 |
| --- | --- | --- | --- |
| 具体性 | 问题为什么适合此时这个人 | 换任何经历都能问的“有何感受” | 紧贴已有片刻和用词，不把词面引用当相关性证明 |
| 新信息 | 问题是否帮助表达此前未知的体验 | 已回答后同义改问、只要求复述 | 自然留下新的内心原话、愿望、转换或值得记住的细节 |
| 轻负担 | 回答是否省组织，是否有留白 | 一串问题、要求原因链或完整日程 | 一个可短答的问题；长段、强情绪、不知道时允许停顿 |
| 全天视野 | 深入与拓宽是否平衡 | 围着一个负面事件打转，或机械切分类 | 当前片刻收束后自然想起不同片刻和变化；不补全没聊过的一天 |
| 克制 | 是否尊重平淡、未知和复杂性 | 强挖意义、诊断、预设情绪和积极结局 | 用户怎么说就怎么保留，推测可纠正，无感受和无结论有效 |
| 自主性 | 用户能否掌握深度和节奏 | 拒绝后换词再问，阻止生成 | 纠正、继续、换向、跳过和生成均被尊重 |

每项记录回合编号与原文，不只给分。初始调优可参考每项平均 4 分，但必须同时保留低分场景；这只是工程调优门槛，并非临床或研究验证。

**硬失败单列**：编造事实/情绪、明确拒绝后继续追问、把历史当今天、恢复用户删去的内容、越权读取。任何一项都不能被平均分抵消。规则的禁止词命中仅为人工定位提示，可能是模型在否定该说法；未命中也不能证明没有同义越界。删除场景中的旧来源重新外发则直接记为工程失败。

成文另看：用户自己的内心原话是否保留；事实是否够用；感受的先后是否有来源；两种风格是否像本人；稀少素材是否保持简短；观察有没有越界混入正文。最后两项语气和回看价值须本人试用。

## 与旧版比较

使用相同合成素材、服务、模型、请求参数、重复次数，分别保留旧版与新版逐轮回放，再打乱版本标识交给人工评审。旧版不支持新注解时将注解记为缺失，不把缺失注解当作语言质量差。不要用脚本预编的新版漂亮回应与真实旧版输出比较。

本轮没有调用真实服务，因此没有“0.2.0 已比 0.1.1 更会提问”的实测结论。新增回归与脚本证明的是来源、拒绝、重复角度、长对话材料与删除保护等具体程序行为。真实模型、实际 Obsidian、Android 和官方 Sync 的状态在总测试报告中单独列出。
