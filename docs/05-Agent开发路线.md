# Agent 开发路线

本文保留原规划的任务定义。实施进度见 [开发看板](task-board.md)，实际验证见 [测试报告](测试报告.md)。顺序优先形成可靠的数据闭环，再改善对话和历史记忆；开发期间使用合成资料，不要求用户逐阶段试用。

## 执行方式

同一个开发 Agent 按架构、实现、评测和复核四种责任视角顺序工作，不以创建多个 Agent 为必要条件，也不自动创建新聊天。每个阶段完成后记录证据并继续下一阶段。只有真实阻塞、影响已确认产品行为的重大范围变化或需要外部权限的动作，才向用户提出具体问题。

开始开发时建立任务看板，每个任务记录 `todo / doing / done / blocked`、依赖、变更文件、检查结果和待验项。不能用写完代码代替通过条件，也不能把未具备环境的真机测试记为通过。

## M0：验证高风险技术选择

依赖：阅读全部规范。产出：技术决策记录 ADR-001 至 ADR-004、环境能力表、最小验证用例。

| 任务 | 工作 | 通过条件 |
| --- | --- | --- |
| T00.1 | 核对 Obsidian API、版本与移动限制 | 固定兼容基线、类型包及用到的 API；列出实测与文档验证的区别 |
| T00.2 | 验证单一模型网关 | 假 HTTP 响应测试鉴权、路径拼接、异常、超时、迟到响应；实际凭据缺失不阻断其他工作 |
| T00.3 | 验证 SecretStorage 方案 | 代码契约、缺失处理与命名空间测试通过；无真机时标出 Android 持久化待验 |
| T00.4 | 验证事件段与归并 | 两个模拟设备断开、接续、乱序、重复和并发事件不丢已保存输入；抑制状态不误恢复 |
| T00.5 | 验证人工编辑及事务恢复设计 | 生成中改正文、保存中断后重开等用例有明确可执行路径 |

ADR 记录：问题、候选、决定、依据、验证结果和修订触发条件。若个别选择不可行，优先调整内部实现，不偷换用户行为或声称全部服务兼容。真实 Sync 与 Android 检查可以进入完整版本最终验证，不要求用户在此阶段参与。

## M1：插件骨架、标签页与配置

依赖：M0 的兼容基线与模块契约。

| 任务 | 工作 | 对应需求 |
| --- | --- | --- |
| T01.1 | 创建工程、严格类型、构建与检查脚本、锁定依赖 | P13 |
| T01.2 | 注册独立 ItemView、命令及已有标签聚焦；关闭释放监听 | P02 |
| T01.3 | 模型设置、凭据引用与最小连接测试 | P01 |
| T01.4 | 入口增改、排序、开关；风格和目录设置 | P03、P08 |
| T01.5 | 允许资料范围与首次说明 | P12 |

通过条件：可构建和载入；无配置时有明确引导；不存在插件侧栏或弹窗式记录界面；设置无明文密钥；入口关闭后对话策略不再主动覆盖它。设置组件需兼容所声明最低版本。

## M2：本机持久化、恢复与同步归并

依赖：M1 的插件与配置。此阶段暂用确定性假模型。

| 任务 | 工作 | 对应需求 |
| --- | --- | --- |
| T02.1 | 事件 schema、分段存储、写入队列、完整性验证 | P06 |
| T02.2 | 会话投影、输入草稿、预览草稿与版本保存 | P06、P09 |
| T02.3 | 文件变更监听、远端段归并、因果缺失与并发分支处理 | P06 |
| T02.4 | schema 迁移、损坏记录保留与恢复入口 | P06、P13 |
| T02.5 | 会话日期、午夜与跨设备日期继承 | P06、P10 |

通过条件：模拟设备 A 记录后 B 可恢复；网络失败与关闭重开不丢已保存内容；未发送文字不被当作事实；重复事件不产生重复消息；不同日期不串档；存储失败不能伪报已保存。

## M3：可控的 AI 对话

依赖：M2。历史相关功能先由显式假证据驱动，真实检索在 M5 加入。

| 任务 | 工作 | 对应需求 |
| --- | --- | --- |
| T03.1 | 单模型网关、请求版本与错误分类 | P01、P13 |
| T03.2 | 独立对话提示词、结构校验、来源候选提取 | P04 |
| T03.3 | 事件和问题记忆、语义反重复、自然收束与转题 | P04、P05 |
| T03.4 | acknowledge 动作与继续问我按钮 | P04、P05 |
| T03.5 | 主动后续事项、抑制和用户重开契约 | P12 |

通过条件：一次至多一个主问题；只回应时不会自动连续发问；继续问我会提出有效下一问题；已回答结果不再次追问；平淡话题可转题；跳过后跨日期、跨设备不再主动追问；模型无法通过输出自行解除抑制。

## M4：正文、观察、预览和归档闭环

依赖：M3。

| 任务 | 工作 | 对应需求 |
| --- | --- | --- |
| T04.1 | 两种正文风格、来源映射和事实校验 | P07、P08 |
| T04.2 | 独立 AI 观察任务、错误隔离与预览编辑 | P07、P09 |
| T04.3 | 同标签整页切换、返回对话保持编辑草稿 | P09 |
| T04.4 | 年月目录、可读问答投影、双向链接 | P10 |
| T04.5 | 归档事务、备份、重复保存与中断恢复 | P09、P10 |
| T04.6 | 追加 / 重新整合，编辑优先与版本冲突 | P11 |

通过条件：完整闭环可运行；只一条素材也能生成；推测不混入正文；观察失败不清空正文；人工删除不被旧问答恢复；重新整合只使用当前正文和新回答；双击保存与恢复不会重复追加。

## M5：受控历史资料和长期观察

依赖：M4；M3 已具备记忆接口。

| 任务 | 工作 | 对应需求 |
| --- | --- | --- |
| T05.1 | 白名单内 Markdown 检索与预算控制 | P12 |
| T05.2 | 证据 ID、文件变更、引用与失效处理 | P07、P12 |
| T05.3 | 后续事项提取和受抑制事项过滤 | P12 |
| T05.4 | 长期模式证据门槛、AI 观察不循环入证据 | P07 |
| T05.5 | 撤销资料授权、取消旧请求和清理缓存 | P12 |

通过条件：未允许文件不读不发；删除授权后旧缓存不继续使用；过去事件不写成今天；观察链接可解析；两个不同日期才允许提出谨慎的重复模式；历史 AI 观察不证明自身。

## M6：完整工程检查、双端准备和小范围交付

依赖：M1—M5 的必需任务。

- T06.1：执行第 06 份文档的工程回归、AI 固定场景与构建检查。
- T06.2：在可用的 Obsidian 测试仓库验证载入、关闭、重开、恢复和卸载行为。
- T06.3：桌面移动模拟与窄屏检查；有已授权真机时完成 Android；否则形成待验脚本。
- T06.4：提供 Sync 设置和插件安装指引，不读取或擅改用户真实仓库。
- T06.5：制作 `ai-diary-0.1.0.zip`、构建证据、校验值、中文使用说明、变更记录和回退说明。
- T06.6：复核密钥泄漏、权限边界、用户编辑保护、事件归并和模块卸载资源清理。

通过条件：所有可执行必需检查通过；待验真实环境项目准确列出；包内无私人资料和密钥；源码能用锁文件重建。若没有真实模型评测结果，应标为“工程版本，模型体验待验”，不能标为模型质量已通过。

## M7：完整版本用户试用、修订与版本冻结

这是用户第一次需要参与主观体验与实际环境确认的阶段。集中试用问答、两种风格、历史观察、补记、双端接续和异常恢复。

根据反馈先修复数据丢失、事实错误、抑制失效和人工编辑覆盖，再改善提问自然度与个人语气。只重跑受影响测试及必要回归。试用通过后冻结小范围版本；公开社区发布另列任务，不能顺手执行。

```text
已执行检查及实际结果：
未执行检查及原因：
已知问题：

```

阶段完成不必等待用户确认。预计工期由接手 Agent 在环境核对后给出，按可运行产物与通过条件安排，不以没有证据的“几天就能全部完成”承诺替代计划。
