# 0.2.0 工程测试报告

日期：2026-10-12。版本性质：体验重构工程试用包。真实模型的自然度、个人语气、实际 Obsidian、Android 软键盘与官方 Sync 仍待验证；本报告不把合成回放或浏览器当作这些验证。

## 交付范围

- 私人手记风格的开始、回顾、文章预览与编辑界面，明暗主题和手机宽度适配。
- 可直接开口；轻提示不变成用户事实；自定义入口收纳，全部关闭也可自由回顾。
- 带原文来源的全天片段、感受、念头、期待和变化索引；聚焦片段、继续、换问法、寻找另一片刻与持久跳过。
- 单服务单模型每轮选择有依据的角度，允许省略复述、只回应或留白；对话格式/语义共用一次修复机会，至多两次请求。
- 截断否定、预设情绪、过度解读、泛问与部分重复角度检查；用户纠正和拒绝不成为必须补齐的缺口。
- 正文两种风格均优先保留用户内心原话与体验变化，事实作背景；未表达感受时不补造。
- 当前正文优先、问答互链、补记、幂等归档和中断恢复保留，0.1.1 的配置保存修复保留。

## 发现并修复的问题

1. 显式换片刻时仍可能优先追问旧片段：收紧 guide 与动作校验，模拟器也必须遵守真实控制语义。
2. 单纯恢复光标仍会重建输入节点：新增同页 DOM 同步，保留 textarea 与完整祖先链；刷新、自动保存后无 blur、无受保护节点移除。正文和观察编辑同测。
3. 撤回授权后，旧 AI 引用可能经消息历史外发：消息记录直接与继承的历史来源及哈希，发请求和采用响应前都检查；撤权、改写、删除后排除派生消息及问题。原始本地问答保留。
4. “先不聊这件事”只靠按钮才抑制：文字表达同样持久生效，无 thread 时可由聚焦片段建立具体事项。
5. “早上没有焦虑，下午开始焦虑”被错误归为全否定：按分句与提问时段判断；完整否定不能被截成肯定引文。
6. 旧模型回应无新注解时仍须接续：旧用户原文可构建情境索引，不推断感受；来源不明的旧 AI 文本保留本地，不自动重新发送。

## 数据兼容与人工编辑

事件保持 schema v1，使用 assistant-message 与 topic-changed 的可选字段，未批量改写旧事件或正式日记。体验线索可由已保存消息重建，新版本校验注解来源；旧版本可以忽略额外字段，但没有新版回顾与派生来源保护能力。回退仍需完整数据备份。

写作输入仅为当前正文/编辑稿与新增用户回答；体验图谱、旧问答、AI 推测和历史资料不充当重新整合正文的额外事实。删文与补记回归继续通过。跳过影响主动追问，既不删除本地原记录，也不等同于删除日记素材。

## 真实模型与用户体验

当前没有使用用户密钥或真实服务。eval-contract.json 的 realModelExecuted=false，六维评分均为 pending；不能据36/36合成结果声称真实模型已更自然、更深入。

真实回放须显式配置环境并运行 --real，具体命令、费用与人工评审步骤见《问答质量评测》。人工分别检查具体性、新信息、轻负担、全天视野、克制、自主性，记录具体回合。格式通过与本人愿意继续说是两种不同证据。

## 已知边界

- 问题规则覆盖可检查的常见越界，不能证明所有语义重复、诱导或幻觉都被识别。
- 单模型的实际提问能力和接口兼容性须用所选服务验证；首版仍为文本 Chat Completions 非流式。
- DayMap 是回顾索引，不是完整行程或精确情绪测量。来源不明的旧 AI 消息不重发，旧会话可能需要少量澄清。
- 长会话在对话中使用全天索引和近期消息，原始记录全保留；超出请求预算时保留内容并提示，未开发自动无限上下文。
- 本地历史检索仍有候选与片段预算；当前正式日记与跨设备冲突需版本检查，不提供全局锁。
- 停止等待不保证服务端处理和计费已经停止。

## 安装与集中试用

使用 ai-diary-0.2.0.zip，关闭插件并覆盖 main.js、manifest.json、styles.css，保留 data.json、日记、问答与接续数据。先在测试仓库确认配置，再集中体验普通的一晚和想深入的一晚。

优先检查：是否更容易想起具体片刻、是否愿意继续说、是否留下自己的内心原话；然后检查换问法、换片刻、拒绝、预览编辑、补记与双端接续。实际验证结果与工程报告分开记录。
