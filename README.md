# AI 问答日记 · Obsidian 插件

插件版本：0.4.0 工程候选版，2026-10-14—15（Asia/Shanghai）。

0.4.0将日记生成改成“有效问答→事实文档与简短篇章建议→结合原文全文撰写”，补回短回答的指代和感受归属。提问从整段判断重心与问题价值，允许带过平淡、留空间或自然换片段，没有情绪词表、固定心理分类或问句数量门禁。独立观察与周月回顾继续保留。

界面沿用Obsidian主题，授权、编辑优先和归档保护保留。本轮仅同10篇虚构样本进行真实API版本对照，另有8个提问前文回放；指代改善较明确，行文改善有限，原始不足保留。最后4.0.3写作候选被上游429阻止，未完成实测，不将4.0.2成功稿冒称最终候选实测。见 [研究与取舍](docs/15-连贯成文与有用提问研究.md)、[测试报告](docs/测试报告.md)、[本轮文件清单](docs/16-十篇测试文件与真实记录.md)。0.3.0的62天记录及旧包保留。实际Obsidian、Android、Sync另行验证。

Node 22+。Chromium需已安装，可用 `npx playwright install chromium` 准备。本轮不新增/运行性能或单元测试。十篇脚本为scripts/coherence-eval.ts，素材tests/fixtures/coherence.ts，读写test-results/coherence隔离仓库；只有明确授权后才能运行当前凭据读取，不属于插件发行文件。0.3.0两个月脚本作为历史保留，未在本轮全量重跑。

产品帮助用户把已知的经历说出来，将组织和措辞交给 AI：晚上打开 Obsidian 独立标签页，选择话题入口，按自己的节奏对话，生成并编辑预览，确认后归档。首版面向自己和少量朋友，以 Windows、Android 和 Obsidian 官方 Sync 为主要使用环境。

## 必须保住的体验

1. **用户说素材，AI 负责组织。** 接受短句、口语、跳跃叙述与平淡的一天。
2. **深入而有分寸。** 顺着已表达的感受聊，逐个话题自然收束，再覆盖其他入口；可以只回应而不提问。
3. **主动权在用户。** 随时生成；“继续问我”触发新问题。跳过某件事后，停止主动追问，直到用户重新提起。
4. **正文忠实，观察分开。** 第一人称正文不写入 AI 推测；观察明确不确定性，长期模式附历史依据。
5. **用户编辑优先。** 补记可追加或重新整合；重新整合使用当前正文和新增回答，不从旧问答复活已删内容。
6. **能恢复、能追溯。** 对话、草稿和停止追问状态持久化；问答与日记分别存放且互链。

## 首版工程默认值

下表是为使 Agent 可开工而给出的技术选择，并非访谈中逐项确认的用户偏好。Agent 可根据验证结果修订实现，需记录理由并保持上述产品行为。

| 项目 | 默认方案 |
| --- | --- |
| 技术栈 | TypeScript、Obsidian 官方 API、esbuild、Vitest；界面优先使用原生 DOM 和 Obsidian 样式 |
| 模型接入 | 单服务、单模型；首个适配器为 Chat Completions 兼容接口，手工填写模型名称 |
| 请求方式 | 非流式优先；应用层取消、超时和迟到响应丢弃；不以支持流式为首版前提 |
| 记忆检索 | 仅用户允许的 Markdown 资料；本地关键词与时间检索，优先使用最小相关片段 |
| 凭据 | 优先 SecretStorage，普通配置仅存引用；默认每台设备配置自己的凭据 |
| 同步 | 使用官方 Sync 传递仓库文件；按设备和写入实例分开记录事件，避免共享 JSON 状态成为唯一事实来源 |
| 兼容基线 | 暂按 Obsidian 1.11.5 或以上设计，M0 核对 API、依赖与实际运行版本后冻结 |

## 开发顺序与完成定义

`M0 技术验证 → M1 插件骨架与设置 → M2 数据恢复与同步 → M3 对话引擎 → M4 日记与归档 → M5 历史记忆 → M6 完整检查与打包 → M7 完整版用户试用与修订`

Agent 连续完成 M0—M6，不要求用户逐阶段试用或批准例行实现选择。没有真实模型密钥、Android 真机或 Sync 环境时，继续完成模拟测试与工程工作，在报告中将真实环境验证标为待验，不伪造通过结果。M7 在完整版本交付后集中开展。

工程完成意味着有可安装插件包、可重复构建的源码、通过记录、使用说明和回退方法。产品完成还需要完整版本试用确认：不显得盘问、正文像用户自己、回看能留下重要细节。
